# INPSan Official Checkpoint — CP-PD-001

**Title:** Unified Product Doctrine — Human-Owned UX, AFTA/Passive-Defense Alignment, Predictive Intelligence, Central Management and Engineering Quality  
**Recorded:** 2026-09-28  
**Parent:** CP-KB-001 / CP-SEC-001  
**Status:** APPROVED CROSS-CUTTING PRODUCT BASELINE

## 1. Decision

All INPSan 3.3+ development shall progress under one integrated product doctrine. Product engineering, knowledge-based evidence, security certification readiness, passive-defense/cyber-resilience requirements, UX provenance, predictive intelligence, centralized management, maintainability and performance engineering are not separate end-stage activities.

## 2. Human-owned UX requirement

INPSan UI/UX shall be company-owned and demonstrably based on documented human engineering decisions.

Required evidence:
- personas/workflows;
- company-authored requirements;
- design system;
- rationale and revision history;
- usability/field review;
- implemented source/tests.

Generic/template-like dashboard design that obscures operational intent is rejected.

## 3. Experience-driven monitoring/alarm/reporting

The product shall explicitly translate long-term R&D/team experience with enterprise storage, SAN/NAS, network/security infrastructure and organizational IT operations into:
- widgets;
- alerts;
- reports;
- correlation rules;
- operator guidance;
- incident context;
- predictive indicators.

Each major item must state the operational problem and intended IT persona.

## 4. AFTA/security evaluation alignment

The publicly available AFTA-oriented network-application requirements are incorporated as an applicable Web/API/control-plane engineering baseline.

Focus areas:
- audit/log;
- cryptography;
- identification/authentication;
- access/data protection;
- security management;
- protection of security functions;
- resource/access/session behavior;
- trusted channels;
- HTTPS/TLS/certificate validation/SSH as applicable;
- update/integrity.

Final certification conformance remains laboratory/version/category-specific.

## 5. Passive-defense/cyber-resilience alignment

Roadmap requirements now explicitly include:
- monitoring/detection/warning/situational awareness;
- predictive/early-warning operation;
- continuity of essential storage services;
- resilience and recoverability;
- dependency/redundancy visibility;
- insider/privileged-operation accountability;
- vulnerability reduction;
- readiness/incident-response/recovery evidence.

## 6. Customizable operations workspace

Per-user and per-organization customization is mandatory in the target architecture while security policy remains authoritative.

Includes:
- saved dashboards/views;
- widget/layout customization;
- role-specific presets;
- organization thresholds/policies;
- reports/scheduling;
- maintenance/escalation settings;
- audited policy-locked controls.

## 7. Local Predictive Intelligence

Local-first predictive architecture is confirmed as a strategic proprietary R&D workstream.

Data sources include operational metadata/telemetry:
- IOPS/throughput/latency/queue depth;
- capacity growth;
- SMART/media/HBA/FC/iSCSI/network errors;
- ARC/memory pressure;
- hardware temperature/health;
- alert/event history;
- workload seasonality.

Development sequence:
data quality -> deterministic baselines -> anomaly detection -> forecasting -> failure-risk estimation -> explainable early warning -> recommendation assistance.

Customer payload-content analysis is excluded by default.

## 8. Central Manager

Centralized secure management for multiple INPSan nodes remains mandatory.

The manager must:
- securely enroll nodes;
- use authenticated protected channels;
- aggregate health/alerts/capacity/security posture;
- centrally orchestrate policy/config/update with audit and rollback;
- preserve safe local operation if Central Manager is unavailable.

## 9. Maintainability/source engineering

All proprietary source shall include meaningful explanation of purpose, interfaces, assumptions, security/operational intent and non-obvious rationale.

The objective is to reduce key-person dependency and permit qualified engineers to maintain and extend modules from source + documentation + tests.

## 10. Security and attack-surface reduction

Mandatory modules/workstreams:
- independent AuthN;
- RBAC/object/scope authorization;
- privileged MFA;
- security audit;
- secrets/certificates;
- TLS;
- secure operation broker;
- signed update/integrity;
- storage-protocol security policy;
- SAST/SCA/DAST/secret scanning/SBOM;
- independent penetration testing;
- release security gates.

## 11. Performance/benchmark requirement

Every production service/module must have measurable resource and latency budgets.

Minimum metrics:
CPU, RAM/ARC interaction, storage footprint/growth, API/UI latency, alert latency, startup/recovery, security/KDF cost, predictive inference cost and future Central Manager scaling.

## 12. Master traceability rule

Every major capability shall follow:

Experience / Requirement  
-> Standard / AFTA / Passive-Defense Need  
-> Architecture / ADR  
-> Source  
-> Test  
-> Benchmark / Security Evidence  
-> Release / Checkpoint

No design or prototype is labeled PASS without implementation and retained evidence.
